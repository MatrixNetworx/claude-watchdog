# Claude Watchdog v5.3 — coverage and integrity update

- Fix: scan transcripts every interval, even when no Claude process is detected.
- `--report` now labels the report v5.3.
- `tools/watchdog_coverage.py` performs read-only tool-ID reconciliation against retained event logs. It does not restore records.
- `tools/watchdog_integrity.py` checks log file disappearance, inode changes, truncation, same-size edits, and non-append rewrites. Its independent 60-second journal is stored outside `~/WatchDog`.
- Run `sh scripts/start-integrity-linux.sh` separately after installing. Use an S6 service for supervision and automatic restart; the included launcher is not supervised.
- Expected rotation causes inode-change/missing-file alerts: investigate rather than treating alerts as proof of tampering.
- This is a baseline detector, not tamper-proof: a privileged attacker can modify local state and logs, and deletion between samples may go undetected. Use off-host checkpoints for stronger assurances.
- The integrity monitor is independent but it does not yet alert when the main Watchdog process stops. Add service supervision for that guarantee.
- The source transcript comparison does not prove missing records were deleted: deduplication, log rotation and original ingestion gaps can explain mismatches.
- Do not run `--setup` during upgrade; installer preserves `~/WatchDog`.

## Usage

```sh
sh scripts/install-linux.sh
sh scripts/start-linux.sh
sh scripts/start-integrity-linux.sh
python3 ~/.local/bin/watchdog_coverage.py --log-dir ~/WatchDog --root ~/.claude
python3 ~/.local/bin/watchdog_integrity.py --once
```
